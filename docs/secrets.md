# Secrets + SOPS workflow

Frostflake now relies on [sops-nix](https://github.com/Mic92/sops-nix) with
Age recipients. Secrets stay encrypted at rest, decrypt only on the target
machines, and are wired into the NixOS modules via `frostflake.secrets`.

## Directory layout

```
secrets/
  README.md            # high-level guidance (no encrypted blobs committed)
  hosts/
    <hostname>.yaml    # per-host SOPS files (create as needed)
  shared.yaml          # optional shared secrets (pam_u2f mappings, etc.)
```

`.sops.yaml` controls which Age public keys can decrypt each file. Replace the
placeholder key with the real recipients before adding any secrets.

## 1. Generate or recover your Age key

```sh
# Uses ~/.config/sops/age/keys.txt by default
$ make age-key
```

The target file is exported via `SOPS_AGE_KEY_FILE` (defaults to
`~/.config/sops/age/keys.txt`). The make target prints the corresponding public
key so you can paste it into `.sops.yaml`.

To copy the Age identity onto a host so `sops-nix` can decrypt during
activation:

```sh
$ sudo install -D -m600 ~/.config/sops/age/keys.txt /var/lib/sops-nix/key.txt
```

Repeat per host (ideally, generate a dedicated key on each machine).

## 2. Declare recipients in `.sops.yaml`

1. Replace `age1replace_me_with_real_public_key...` with the operator key.
2. Optionally add additional anchors (e.g., per-host keys) and reference them in
   the `creation_rules`.

`sops` refuses to edit files until valid recipients exist, which prevents
accidental plaintext commits.

## 3. Create encrypted files

```sh
# Create/edit a shared secret bundle (e.g., pam_u2f mappings)
$ make secret-edit FILE=shared.yaml

# Create/edit per-host blobs
$ make secret-host HOST=avalanche
```

By default the secrets module expects:

- `secrets/shared.yaml` to contain a `pam_u2f_mappings` key. Its contents are
  provisioned to `/etc/security/u2f-mappings` and must include the entries
  generated by `pamu2fcfg`.
- `secrets/hosts/<hostname>.yaml` to store host-specific values (you can add any
  additional keys here and expose them via `frostflake.secrets.extraSecrets`).

Commit only the encrypted `.yaml` files; the Makefile never copies plaintext
into the repo.

## 4. Deploy

Once the encrypted files exist and each host has the corresponding Age private
key at `/var/lib/sops-nix/key.txt`, rebuild normally:

```sh
# Linux
$ make switch HOST=Avalanche

# macOS
$ make darwin HOST=Glacier
```

`sops-nix` decrypts the requested blobs during activation and writes them to the
paths defined in `modules/system/secrets.nix`.

## 5. Rotate or add recipients

1. Generate a new Age key (`make age-key` on the new machine, copy the public
   key).
2. Add the public key to `.sops.yaml` and rerun `sops updatekeys secrets/*.yaml`.
3. Remove old keys once every host has been re-encrypted with the new set.

## 6. Verification

```sh
# Ensure every encrypted file contains SOPS metadata and can be decrypted
$ make secrets-verify
```

If verification fails, double-check that `SOPS_AGE_KEY_FILE` points at the
private key and that `.sops.yaml` lists the matching public key.
